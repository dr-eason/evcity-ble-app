# EVCITY AC 蓝牙 App：iOS 版

和 Android 版（`AC06/tools/ble-finder/`）是同一个 App：同一份 Vue 界面，换了一层原生外壳。

- 界面：`ble-finder/ui` 编出来的那个 `index.html`，装在 `WKWebView` 里。iOS 这边不另存一份界面源码。
- 蓝牙：CoreBluetooth。对页面提供和 Android 一样的 `window.EVC`，事件一样走 `onBle(...)`。
- 版本 3.0.4（build 3004），显示名 EVCITY AC，最低 iOS 15。Bundle ID 先用占位的 `com.evcity.ac06ble`。

编 iOS App 必须用 Mac 和 Xcode。没有 Mac 时用 GitHub Actions 的 macOS 机器编（见第 6 节）。

> 这套工程是在 Linux 上写的，那台机器上没有 Xcode，也没装上 Swift。**到写这份说明为止，Swift 代码还没有被编译过，
> 也没有在真机上连过充电桩。** 第一次在 Mac 或 GitHub Actions 上编时可能要修几处编译错误，真机联调见第 9 节。

```

  App/Resources/

```

## 2. 在 Mac 上编

要装的东西：Xcode（App Store）、Node 20 或 22、XcodeGen。

```bash
brew install node xcodegen

cd AC06/tools/ble-ios          # 公开仓里是 cd ios
./build_ui.sh                  # npm ci + npm run build，把 index.html 拷进 App/Resources/Web，生成图标
xcodegen generate              # 生成 EVCITYAC.xcodeproj
open EVCITYAC.xcodeproj        # 用 Xcode 打开，选一个模拟器，点运行
```

`build_ui.sh` 自己找界面源码：先看 `../ui`（公开仓的布局），再看 `../ble-finder/ui`（AC-V2 的布局）。
改了 Vue 源码后要重跑一次。改了 `project.yml` 或加减了 Swift 文件后要重跑 `xcodegen generate`。

注意：`npm run build` 会按 `ui/vite.config.js` 把单文件的 `index.html` 写到 `ui` 的上一级 `assets/`，在 AC-V2 里就是
Android 用的 `ble-finder/assets/index.html`。也就是跑 `build_ui.sh` 等于顺便重编了 Android 的界面文件。源码没改时内容不变。

命令行编模拟器版（不签名）并跑单元测试：

```bash
xcodebuild build test \
  -project EVCITYAC.xcodeproj -scheme EVCITYAC -configuration Debug \
  -destination 'platform=iOS Simulator,name=iPhone 16' \
  -derivedDataPath build/DerivedData \
  CODE_SIGNING_ALLOWED=NO EVC_MOCK_BLE=1
```

模拟器名字随 Xcode 版本变，`xcrun simctl list devices available` 看本机有哪些。编好的 App 在
`build/DerivedData/Build/Products/Debug-iphonesimulator/EVCITYAC.app`。

只跑逻辑的单元测试（不用模拟器，几秒钟）：`swift test --package-path Core`。

## 3. 模拟器和 Mock BLE

iOS 模拟器没有蓝牙，CoreBluetooth 在里面什么也扫不到。所以有一个 **Mock BLE 模式**：蓝牙调用不去 CoreBluetooth，
由页面里的一台假充电桩（`mock-evc.js`）应答，能走完扫描、连接、输密码、充电页、设置、固件升级这些界面。

| 情况 | 用什么 |
|---|---|
| 模拟器 | 总是 Mock |
| 编译时带 `EVC_MOCK_BLE=1`（命令行，或写进 `Config/Local.xcconfig`） | 总是 Mock，真机上也是 |
| Debug 版，在 Xcode 的 Scheme → Run → Arguments → Environment Variables 里加 `EVC_MOCK_BLE=1` | Mock |
| 其余，也就是正常编的真机版 | 真蓝牙 |

Mock 里有三台假桩（EVC-AC06-0001 到 0003）。密码填任意 6 位数字都算对，只有 `000000` 算错，用来看「密码不对」的界面。
假桩按固件的格式每秒发一次状态行，开始 / 停止充电、各项设置的读写、固件升级的每一步都有应答（升级不会真的写什么）。

没有 Mac 时也能看界面：`node tools/mock-web/shots.mjs <输出目录>` 用电脑上的 Chrome 按 iPhone 尺寸截图，
注入的就是 App 里那两个脚本。

## 4. 和 Android 的对应关系

页面调原生（`window.EVC`）：

| 方法 | Android | iOS |
|---|---|---|
| `scan()` | 正在扫就停，否则开始扫 | 一样。第一次调用时系统弹蓝牙权限框，用户点完自动开始扫 |
| `stopScan()` | 停扫 | 一样 |
| `connect(address)` | 停扫，等 200 ms，`connectGatt` | 一样的顺序，`CBCentralManager.connect`。`address` 见下面「地址」 |
| `disconnect()` | 关 GATT，回扫描页，提示「蓝牙已断开」 | 一样 |
| `send(text)` | 末尾补换行排队发；空的、带换行的不发 | 一样 |
| `saveGate(address, pin)` | SharedPreferences `evc_gate`，6 位才存，否则删 | UserDefaults 的 `evc_gate`，规则一样 |
| `loadGate(address)` | 同步返回 | 同步返回（加载页面时把整张表交给页面） |
| `locale()` | 系统语言 | 系统首选语言，同步返回 |
| `appVersion()` / `appBuild()` | `PackageInfo` 的 versionName / versionCode | Bundle 的 `CFBundleShortVersionString` / `CFBundleVersion`（Base.xcconfig 的 `EVC_VERSION` / `EVC_BUILD`），加载页面时写进 `__evcInit`，同步返回。首页底部和「设置 → 关于」显示；取不到时界面用编译时的版本兜底，再没有显示“—” |
| `mtu()` | `requestMtu(247)` 协商到的值，初值 23 | 系统自己协商，按「每次最多能写多少 + 3」算，封顶 247，初值 23 |
| `linkFast(on)` | 连接间隔调短 / 调回 | iOS 不让 App 改连接间隔，这一项不起作用；改成升级期间不让屏幕自动锁 |
| `heartbeatTime(on)` | 心跳带不带手机时间 | 一样，格式一样 |
| `restart()` | 杀进程再拉起来 | App 不能自己重启：停扫、断开蓝牙、把页面重新加载一遍 |

原生调页面：`onBle({t:"note"|"page"|"scan"|"line"|"devs", …})` 五种事件和 Android 一样，提示的文字也一样（界面按这些文字做翻译）。
页面没加载完时事件先排队。收到的行按同一张表过滤，只放行认识的行首。

其它：

- **地址**：iOS 拿不到蓝牙 MAC。`devs` 里的 `addr` 是系统给这台桩的一个 UUID，同一台手机上对同一台桩是固定的，
  记住的密码就按它存。界面上显示地址的地方看到的是这个 UUID，不是 MAC。
- **返回**：Android 的返回键 / 侧滑调 `window.evcTryBack()`。iOS 上从屏幕左边缘往里滑调同一个函数。
  二级页回上一级；预约、设置（M01 是记录、设置）标签回立即充电；在立即充电页和点「断开蓝牙」一样断开、回扫描列表。
  只有停在扫描列表上函数返回 false：Android 这时退出到桌面，iOS 的 App 不自己退出，所以这时什么也不做。
- **`mailto:` 链接**：交给系统的邮件 App。别的外部链接不打开，和 Android 一样。
- **写入**：特征值支持「不带应答的写」就用它，否则用带应答的写；每次最多写 MTU − 3 字节，长的命令切开按顺序发。
- **心跳、读状态**：每秒一条 `HB`；开通知后发 `STATUS`，没收到 `STAT` 就每 700 ms 再问，最多 5 次。
- **后台**：没有开后台蓝牙。App 退到后台或锁屏后会被系统挂起，心跳一停，桩 3 秒后就当手机走了，回来要重连。
  Android 版也没有做后台保活。发固件期间 App 会让屏幕保持常亮，但中途切到别的 App 一样会断。
- **隐私政策**：就是界面里那一页，没有改。里面的文字现在写的是「Android app」和 Android 的权限名，上架前要改，见第 9 节。

### 固件升级选文件

界面用的是网页的 `<input type="file">` 加 `FileReader`，不是原生的文件选择器。WKWebView 自己支持这个控件：
点「选择固件文件」会弹系统菜单，选「选取文件」后从「文件」App 里挑 `.bin`。所以默认什么都不用做。
固件文件要先放到手机上能被「文件」App 看到的地方（iCloud 云盘、隔空投送后存到「我的 iPhone」、微信里「用其他应用打开 → 存储到文件」等）。

系统菜单里还会有「照片图库」「拍照」两项，对选固件没用。如果真机上觉得碍事，或者这个菜单有问题，
把 `Config/Base.xcconfig` 里的 `EVC_NATIVE_FILE_PICKER` 改成 `YES`：这时点按钮直接打开系统的「文件」选择器，
原生读完文件再交给页面，界面代码不用改。这条后备的路还没在真机上试过。

## 5. 真机：证书、UDID、描述文件

要你提供的东西：

1. **Apple Developer 账号**（付费的开发者计划，每年 99 美元）和它的 **Team ID**（10 位字母数字，developer.apple.com → Membership details）。
2. **测试手机的 UDID**。你说的「车牌号」就是它：一串 25 或 40 位的字母数字，每台 iPhone 一个。
3. **证书**和**描述文件**（下面讲怎么做）。

**查 UDID**：手机用线连到 Mac，打开「访达」，点左边的手机，再点手机名字下面那行字，会轮流显示序列号、UDID，右键可以拷贝。
没有 Mac 时，连到 Windows 电脑用「Apple 设备」App 或 iTunes，在摘要页点序列号那一行也会变成 UDID。

**登记设备**：developer.apple.com → Certificates, Identifiers & Profiles → Devices → 加号，填名字和 UDID。一年最多登记 100 台 iPhone。

**登记 Bundle ID**：同一个页面的 Identifiers → 加号 → App IDs → App，填 `com.evcity.ac06ble`（或者你想用的），不用勾额外的能力。
换了的话把 `Config/Base.xcconfig` 里的 `EVC_BUNDLE_ID` 一起改掉。

**最省事的办法（自己的 Mac，开发版）**：把 `Config/Local.xcconfig.example` 拷成 `Config/Local.xcconfig`，填上 Team ID；
Xcode → Settings → Accounts 登录开发者账号；手机连上 Mac，在 Xcode 里选这台手机点运行。Xcode 会自动做证书和描述文件。
第一次运行前手机上要打开「设置 → 隐私与安全性 → 开发者模式」。

**要发给别人装、或者在 GitHub Actions 上打包**，需要自己做证书和描述文件：

| | Development（开发） | Ad Hoc（内部分发） |
|---|---|---|
| 证书类型 | Apple Development | Apple Distribution |
| 能装到 | 描述文件里列的设备 | 描述文件里列的设备 |
| 用途 | 连 Xcode 调试 | 发 `.ipa` 给测试的人装 |

1. 证书：在 Mac 的「钥匙串访问」→ 证书助理 → 从证书颁发机构请求证书，存一个 `.certSigningRequest` 文件；
   到开发者网站 Certificates → 加号，选上表里的类型，上传这个文件，下载 `.cer`，双击装进钥匙串。
   然后在钥匙串里右键这个证书 → 导出，存成 `.p12`，设一个密码。**`.p12` 里有私钥，不要放进任何仓库。**
2. 描述文件：开发者网站 Profiles → 加号，选 iOS App Development 或 Ad Hoc，选上面的 App ID、证书、要装的设备，下载 `.mobileprovision`。
   以后新加了设备，要回来编辑这个描述文件把设备勾上，重新下载。

Ad Hoc 的 `.ipa` 装到手机：Mac 上用 Apple Configurator 或 Xcode 的 Devices and Simulators 窗口把 `.ipa` 拖到设备上。

## 6. GitHub Actions（公开仓）

iOS 的构建不在 AC-V2 里跑，在公开仓 **`dr-eason/evcity-ble-app`** 里跑。公开仓是 AC-V2 的**单向镜像**：主源码在 AC-V2，
公开仓的内容每次由脚本整份生成，不要在公开仓里直接改（第 7 节）。

工作流文件在 AC-V2 里是 `AC06/tools/ble-ios/ci/ios.yml`，镜像后变成公开仓的 `.github/workflows/ios.yml`。
里面的路径是按公开仓的目录（`ui/`、`ios/`）写的。AC-V2 的 `.github/` 下没有它，所以它在 AC-V2 里不会跑。

**什么时候跑**：公开仓里 `ios/**` 或 `ui/**` 有改动的 push 和 PR；或者手动触发。只看这两个目录是为了省 macOS 的分钟数。
固件、屏幕这些本来就不会镜像到公开仓；在 AC-V2 这边，镜像的工作流同样只在这两个目录有改动时才跑，所以提交固件不会触发任何 iOS 构建。
同一个分支上新的一次会取消还在跑的上一次，单次最多 30 分钟。

**默认的任务**（每次都跑）：编界面 → 跑界面的单元测试 → 生成工程 → 编模拟器版（不签名，Mock BLE）并跑 Swift 单元测试 → 把模拟器的 `.app` 打成 zip 上传。

公开仓里跑的界面测试是 `ota-window`、`wifi-rssi`、`modver`、`time-sync`、`profile`、`app-version`（`app-version` 里核对 Android 源码的那一条在公开仓自动跳过）。`lte`、`tz`、`charger-clock` 里还有几项要对照 AC-V2 的固件和 `AndroidManifest.xml`，公开仓没有那些文件，所以不在这里跑。完整的 `node --test AC06/tools/ble-finder/ui/test/` 在 AC-V2 本地跑。

**手动触发**：公开仓 → Actions → 左边选 iOS → 右边 Run workflow → 选分支 → Run workflow。

**下载产物**：Actions → 点进那一次运行 → 页面最下面的 Artifacts：

- `EVCITYAC-simulator`：模拟器版。解压后在 Mac 上把 `EVCITYAC.app` 拖进开着的模拟器，或者 `xcrun simctl install booted EVCITYAC.app`。只能在模拟器里跑，装不到手机上。
- `xcodebuild-simulator-log`：完整的编译日志，编不过时看它。
- `EVCITYAC-release-ad-hoc-ipa`：发布用的 Ad Hoc 真机包（发布证书 +「EVCITY AC Profile Prod」）。这是按设备列表签的，**不能上传到 App Store / TestFlight**。
- `EVCITYAC-test-development-ipa`：测试用的 Development 真机包（开发证书 +「EVCITY AC Profile」，带 get-task-allow）。

产物默认保留 90 天。

**签名的真机包**（默认不跑）：手动触发时勾上 `build_ipa`，`bundle_id` 填描述文件对应的 Bundle ID。
勾上之后会**同时打两份**：一份 development（测试），一份 ad-hoc（发布）。界面上的 `export_method` 已不再决定打哪一份，只是保留兼容。
跑之前要在公开仓加好 Secrets：公开仓 → Settings → Secrets and variables → Actions → New repository secret。

| Secret | 填什么 |
|---|---|
| `APPLE_TEAM_ID` | Team ID（两份共用） |
| `KEYCHAIN_PASSWORD` | 随便定一串，只用来锁 CI 里临时建的钥匙串 |
| `BUILD_CERTIFICATE_BASE64` | 发布证书 `.p12` 的 base64（Ad Hoc / 发布包）：Mac 上 `base64 -i 证书.p12 \| pbcopy`，然后粘贴 |
| `P12_PASSWORD` | 上面这份发布证书 `.p12` 的密码 |
| `BUILD_PROVISION_PROFILE_BASE64` | 「EVCITY AC Profile Prod」描述文件的 base64。这是 **Ad Hoc**（设备列表），不是 App Store，打出来的包不能传到 App Store / TestFlight |
| `BUILD_CERTIFICATE_DEV_BASE64` | 开发证书 `.p12` 的 base64（Development / 测试包） |
| `P12_DEV_PASSWORD` | 开发证书 `.p12` 的密码 |
| `BUILD_PROVISION_PROFILE_DEV_BASE64` | 「EVCITY AC Profile」描述文件的 base64（Development，get-task-allow） |

少了哪一个，任务第一步就报「缺少 Secret：名字」然后停。证书和密码不会打到日志里，临时钥匙串和描述文件在任务结束时删掉。
公开仓的 Secrets 对 fork 来的 PR 不可见，但仍然建议只有自己人能触发这个任务（仓库 Settings → Actions 里可以限制）。

## 7. 镜像到公开仓

```
公开仓 evcity-ble-app                  来自 AC-V2
  ui/                                 AC06/tools/ble-finder/ui（不带 node_modules、dist）
  ios/                                AC06/tools/ble-ios（不带 mirror/、ci/、编译输出、Local.xcconfig）
  .github/workflows/ios.yml           AC06/tools/ble-ios/ci/ios.yml
  README.md  LICENSE  .gitignore      AC06/tools/ble-ios/mirror/public/ 里的模板
  .evc-mirror                         记着来自 AC-V2 的哪个提交
```

脚本：`mirror/mirror_ble.sh <目标目录>`。它把上面这棵树整份做出来放进目标目录，在那里做一个本地提交，
提交说明是 `sync from AC-V2 <提交号>`。只做快照，不带 AC-V2 的历史；**脚本自己不 push**。

- 目标目录不存在或是空的：新建并 `git init`。是上次镜像出来的仓，或者刚 clone 下来的公开仓：清掉旧文件整份重做。
  别的非空目录不碰，除非加 `--force`。目标目录不能在 AC-V2 仓库里面。
- **护栏**：快照做好后先查一遍，只要有 `signing` 目录、`node_modules`，或者 keystore / jks / properties / p12 / pem / key /
  mobileprovision / `.env` / 名字里带 secret 的文件，或者内容里有 PEM 私钥，脚本就列出这些文件、以退出码 3 结束，不提交。
  Android 的签名文件在 `ble-finder/signing/`，不在被拷的两个目录里，本来就不会带过去；护栏是防以后有人把这类文件放错地方。
- LICENSE 现在只写了版权和「许可待定」。定下来以后改 `mirror/public/LICENSE`。

本机先看一眼会镜像出什么（不碰 GitHub）：

```bash
bash AC06/tools/ble-ios/mirror/mirror_ble.sh /workspace/ble-public-preview
git -C /workspace/ble-public-preview ls-files
```

### 让它自动同步

模板在 `mirror/mirror-ble.yml`，现在只是放着，不会跑。启用的步骤：

1. **建公开仓** `dr-eason/evcity-ble-app`（空仓就行，不用勾 README）。
2. **做一对 deploy key**（任意一台电脑上）：`ssh-keygen -t ed25519 -C ble-mirror -f ble_mirror -N ""`，得到 `ble_mirror`（私钥）和 `ble_mirror.pub`（公钥）。
3. **公钥**加到公开仓：公开仓 → Settings → Deploy keys → Add deploy key，粘贴 `ble_mirror.pub` 的内容，**勾上 Allow write access**。
4. **私钥**加到 AC-V2：AC-V2 → Settings → Secrets and variables → Actions → New repository secret，名字 `BLE_MIRROR_DEPLOY_KEY`，
   内容是 `ble_mirror` 整个文件。加完把本机这两个文件删掉。
5. 把 `AC06/tools/ble-ios/mirror/mirror-ble.yml` 拷到 AC-V2 的 `.github/workflows/mirror-ble.yml`，提交、推送。

之后每次往 `ac06-development` 推送、并且改到了 `AC06/tools/ble-finder/ui/**` 或 `AC06/tools/ble-ios/**`，
AC-V2 的这个工作流（Ubuntu 机器，很便宜）会跑 `mirror_ble.sh` 并把提交推到公开仓的 `main`；公开仓收到推送后，iOS 工作流自己开始编。
也可以在 AC-V2 的 Actions 页面手动触发 Mirror BLE app。

这是单向的：只有 AC-V2 → 公开仓。公开仓里的改动不会回到 AC-V2，下一次同步还会被覆盖。

**公开之前想清楚**：公开仓任何人都能看。镜像过去的是 App 的界面源码、iOS 外壳、蓝牙命令的格式（界面源码里本来就有）。
固件、屏幕文件、Android 的签名文件都不会过去。

## 8. TestFlight

给更多人测试、或者不想一台台登记 UDID 时走 TestFlight：

1. 在 App Store Connect（appstoreconnect.apple.com）→ 我的 App → 加号，新建 App，Bundle ID 选登记好的那个。
2. 证书用 Apple Distribution，描述文件类型选 **App Store**（不是 Ad Hoc）。
3. Mac 上：Xcode 选 Any iOS Device → Product → Archive → Distribute App → App Store Connect → Upload。
   每次上传 build 号要比上次大（改 `Config/Base.xcconfig` 的 `EVC_BUILD`）。
4. 上传后等十几分钟处理完，在 App Store Connect 的 TestFlight 页面：
   内部测试（团队成员，最多 100 人）马上能装；外部测试（最多 10000 人，发邮件或公开链接）第一次要过一遍 Beta 审核，一般一两天。
5. 测试的人在手机上装 TestFlight App，点邀请链接安装。不需要 UDID。

现在的 GitHub Actions 只做到 Ad Hoc / Development 的 `.ipa`，没有自动上传 TestFlight。以后要加的话，
需要 App Store 类型的描述文件和一个 App Store Connect API Key，再加一步上传。
